# 구현과 검증 규칙

- 계산 모듈은 import만으로 다운로드·학습·파일 생성을 하지 않는다. 새 패키지에서 audit_tests·legacy를 import하지 않는다.
- config와 contracts를 공통 경계로 사용한다. 알 수 없는 설정 키, 날짜 중복, 해시·분할 불일치는 조용히 보정하지 않는다.
- 실행 폴더는 새로 생성하며 한 실행이 소유한다. 실패 기록도 남기고 성공 폴더를 덮어쓰지 않는다. 입력·설정·seed·환경·소스 revision과 결과 해시를 기록한다.
- 의존성은 pyproject.toml과 requirements-research.lock으로 고정한다. 실행 중 소스 변경은 같은 버전 결과로 인증하지 않는다.
- 수학 변경은 독립 기대값 또는 직접 재적합으로 확인한다. 통과한 검사는 새 변경·실패 근거 없이 반복하지 않는다. 최종 통합 상태에서는 tests 전체를 한 번 확인한다.
- 코드 구현, 실제 실행, 논문 수치 재현을 구분한다. 과거 실행 결과를 최신 소스의 재실행이라고 기록하지 않는다. 미실행·정의 불가 항목에 사유를 남긴다.
- 역사 감사와 기준 원본의 내용을 바꾸지 않는다. 과거 소스는 Git 이력에서 읽고, 새 성공을 옛 FAIL에 덮어쓰지 않는다.
- 사용자 요청 전에는 master 병합·push하지 않는다. 원자료·환경·캐시를 Git에 일괄 추가하지 않는다. 필요한 보고서 그림과 작은 의미 결과만 명시적으로 추적한다.
