# 구현과 검증 규칙

- 진단은 선택한 기준 버전의 원본 해시를 실행 전후에 확인한다. 소스·입력이 달라지면 그 실행을 같은 기준의 결과로 인증하지 않는다. 새로운 개정의 검증은 기존 진단 이력과 기준 버전을 구분해 기록한다.
- 진단 코드에서 원 연구 모듈을 일반 import하여 최상위 다운로드·파일 생성을 일으키지 않는다. 원 함수/AST를 분리해 호출하거나 준비한 임시 폴더에서 원 스크립트를 실행한다. 연구 모듈은 audit_tests에 의존하지 않는다.
- 새 실험에는 독립 기대값과 계산 근거, 원 코드 위치·해시, 입력/seed, 관측값, 허용오차를 남긴다. 구현을 복사한 두 함수의 일치만으로 원 구현 검증을 대체하지 않는다.
- 실험 ID와 발견 ID는 전역에서 유일해야 한다. 보고서의 판정·제목·건수·한계와 JSON 및 증거 참조가 어긋나면 산출물 검증 실패다. findings의 limitations는 문자열 목록이며 없으면 빈 목록이다.
- 감사용 의존성은 audit_tests/requirements-audit.txt로 고정한다. 기존 연구 requirements.txt와 별도로 관리하고, 실행 환경은 기록한 버전과 대조한다.
- 같은 evidence 출력 폴더에는 동시에 두 실행을 쓰지 않는다. 통합 실행 기록의 소스 해시와 증거 파일 해시를 유지하려면 감사 Python 코드 변경 후 run_audit.py를 다시 실행한 다음 check_artifacts.py를 실행한다.
- 진단 변경의 완료 조건은 두 CLI의 정상 완료, 미해결 실행 오류 없음, 원본 보존, 보고서 일관성이다. 연구 결함을 나타내는 FAIL은 근거와 함께 유지한다. 숫자를 맞추려고 기대값·허용오차를 바꿔 숨기지 않는다.
- 기존 master를 기준으로 별도 작업 브랜치에서 변경을 검토한다. 통합·원격 게시 요청 전에는 master에 병합하거나 push하지 않는다.

CSV/PNG는 기존 .gitignore에서 제외된다. 증거의 의미는 JSON/텍스트에도 남기고, 필요한 진단 CSV만 추적 대상으로 명시한다. 임시 실행 환경과 원시 비밀자료를 일괄 추가하지 않는다.
