# 재검증에서 주의할 지점

## 달력과 수익 라벨

README에는 2020년 4월 제외가 적혀 있지만 실제 전처리는 5월도 삭제한다. 제공 원 CSV의 4월 CP3Mx 결측이 월간 차분을 통해 5월로 전파되기 때문이다. 삭제 후 다음 행은 다음 달이 아닐 수 있으므로 retained 행 번호와 월간 달력 차이를 함께 확인한다. March 다음 행이 June이라는 사실만으로 3개월 보유수익이라고 부르지 않는다.

R_t는 월초 t부터 월초 t+1까지의 수익이다. 학습의 `R.iloc[tau+1]`를 볼 때 가격 구간 끝을 먼저 펼친다. 최신 R_t를 사용하는 것이 허용되는지는 결정이 P_(t+1) 관측 전인지 후인지에 달려 있다. 현재 자료에는 실시간 공개일·체결 시각이 없어 그 부분은 추가 입력이 필요하다.

## 같아 보이는 레짐 번호

PCA 열 번호는 고정 경제 축이 아니다. 부호·회전·성분 수가 달라진 두 창의 좌표를 그대로 비교하면 동일한 중심도 다른 것으로 매칭한다. 공통 좌표로 복원한 비교와 단계 사이 분할 일치를 따로 검사한다. 양쪽 확률과 예측을 동시에 순열 변경하면 집계가 같으므로 번호 변화만으로 수익률 편향을 단정하지 않는다.

## Ridge와 평가 관례

고정 λ의 Ridge 계수가 맞아도 λ 선택 점수는 틀릴 수 있다. 절편을 복원하는 analytic LOOCV의 hat diagonal에는 중심화된 회귀 항 외에 1/n이 필요하다. 실제 한 행 제외 재적합으로 후보별 MSE를 비교하면 누락을 드러낼 수 있다. Step3 fallback은 이미 음의 MSE scoring을 명시하므로 기본 R² 오류라고 추정하지 않는다.

Sortino는 현재 음수 월만의 표본 표준편차를 쓴다. 손실 0회·1회에서는 NaN이므로 다른 라이브러리의 downside RMS와 비교할 때 정의를 먼저 맞춘다. 최초 낙폭은 초기 자산 1의 포함 여부를 독립적으로 확인한다.

## 재실행과 파일

Step0의 `_make_synth_prices`는 이름과 달리 Yahoo 다운로드를 호출한다. Step3/4의 ETF 부재 분기는 실제로 합성 수익을 만들어 같은 CSV 이름에 저장한다. 이름에 DEMO가 있다는 이유로 실자료/합성을 판단하지 않고 생성 경로·seed·해시를 확인한다.

원 스크립트에는 최상위 실행문과 중첩·중복 함수가 있다. AST로 함수를 추출할 때 같은 이름의 마지막 정의를 무조건 원 실행의 정의로 간주하지 않는다. 실행한 코드 객체의 시작 줄과 원 분기를 대조한다.

감사 Python 파일을 편집하거나 줄바꿈이 변하면 기존 run_summary의 감사 소스 해시와 달라진다. runner를 다시 실행한 뒤 checker로 확인한다. 옛 영역별 실행 파일의 경로가 없어졌다는 이유로 현재 입력 부재로 판단하지 않는다. Windows 로그의 UnicodeEncodeError는 보존 Python에 `-X utf8`을 주어 재확인한다.
