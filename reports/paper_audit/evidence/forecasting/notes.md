# 예측·집계·lo 비중 감사 (T5)

## 실행과 판정 범위

검사 16개 중 **PASS 11개, FAIL 5개, 실행 오류 0개**다. FAIL은 원 연구 코드에서 관측한 진단 결과이며 감사 실행 실패가 아니다. 모든 허용 오차 비교는 `atol=1e-10, rtol=1e-10, equal_nan=False`를 명시한다.

- 원본 Step2의 `ridge_precompute_B_Hdiag`(163~176행), `ridge_select_lambda_and_predict`(178~191행), 레짐별 적합 루프 AST(258~286행)를 실행했다. 함수 반환 시점의 실제 입력·계수·LOOCV MSE를 계측했으며 원 함수나 AST를 변경하지 않았다.
- Step3의 원 RidgeCV 생성·fit·predict AST(195~199행)와 원 merge·집계 AST(329~341행), Step4의 `long_only_weights`(256~270행)를 실행했다.
- 원 연구 스크립트 전체를 import하지 않고, 다운로드·최상위 파일 저장·전체 백테스트를 실행하지 않았다. 원 코드와 자료를 수정하지 않았다.
- `results.json`에는 각 판단의 입력 fixture·seed·SHA-256, 원본 줄·SHA-256, 독립 기준, 수치, 분류가 있다. `fixtures.json`은 정확한 합성 입력을 저장한다. `execution.json`은 실제 명령·종료 코드·stdout·stderr·버전·소스와 산출물 해시를 저장한다.

독립 Ridge 기준은 `[1, X]` 증강 설계행렬의 정규방정식을 원소별 합으로 만들고 `diag(0, λ, …, λ)`를 더해 풀었다. 절편은 벌점에서 제외한다. LOOCV는 각 행을 실제로 제외하고 절편과 계수를 다시 적합한다. 이 기준은 sklearn과 원 Ridge 함수에 의존하지 않는다. 먼저 손계산 가능한 3행 예제에서 절편 `19/12`, 계수 `3/4`, LOO 예측 `[2.4, 2.5, 1.8]`, LOO MSE `47/20`을 확인했다. 식14·식18의 독립 합산도 손계산을 통과했다.

## 확인된 Ridge 결과

### 정상 적합과 중심화

고정 λ=2, 48행·3변수, 자산 2개·레짐 5개의 원 적합 루프를 비교했다. 원 계수와 독립 정규방정식의 최대 절대차는 **2.2551405187698492e-17**이다. 복원 절편과 최종 예측도 모두 일치했다(FOR-002). 설명변수의 평행이동에 계수가 불변이고 목표의 평행이동만큼 예측이 이동했다(FOR-003). 따라서 이 결과는 고정 λ의 Ridge 계수·절편 복원 오류를 지지하지 않는다.

### Analytic LOOCV의 절편 항 누락

원 Step2는 레짐별 X와 y를 전체 선택 부분집합에서 중심화하고, `Xc B`의 대각만으로 잔차를 나눈다. 절편을 다시 적합하는 회귀의 전체 hat 대각은 `1/n + diag(Xc B)`다. 코드가 빠뜨린 `1/n`은 seed=4, n=8 반례에서 **0.125**다.

같은 8개 λ 후보에 대한 원 함수의 실제 MSE와 한 행씩 제외한 독립 재적합 MSE의 최대 절대차는 **0.978533913197319**다(FOR-004). 원 분모에 `1/n` 항만 반영한 진단 계산은 독립 재적합 MSE와 허용 오차 내에서 일치한다. 이 보정은 원본 코드에 적용하지 않았다.

| 비교 | 원 Step2 analytic LOOCV | 절편 포함 직접 재적합 |
|---|---:|---:|
| 선택 λ | 1.9306977288832496 | 13.89495494373136 |
| 해당 λ의 직접 재적합 MSE | 1.3793525621039842 | 1.3588553219342276 |
| 합성 질의점 예측 | 4.184991194792493 | 2.8806423113827447 |

선택 λ가 달라지는 반례와 예측 차이 **1.3043488834097485**를 FOR-005에 보존했다. 이는 **고정 PCA 좌표에서 회귀 자체의 LOOCV 오류**다. PCA·군집을 각 CV fold에서 다시 추정하거나 시간순 검증을 해야 한다는 별도 주장과 섞지 않는다. 원문이 λ·CV 방법을 충분히 명세하지 않았다는 사실도 원 코드가 주장하는 fast LOOCV의 수치 불일치와 구별한다.

**위 값은 합성 8행의 진단이며 실제 ETF 수익률 단위·성과 차이 추정이 아니다.**

### 소표본 fallback과 시간 상한

원 루프의 레짐별 학습 후보 수를 `[0, 5, 6, 10, 26]`으로 설정하자 실제 적합 표본 수는 `[47, 47, 6, 10, 26]`이었다(FOR-006). 0개와 5개 레짐은 같은 전체 47행을 사용해 예측도 같아졌다. `<6` 기준과 global fallback은 원문 미명세 추가 정책이다. 저장하는 `n_Ri`는 fallback 전 표본 수이므로 실제 적합 표본 수를 뜻하지 않는다. 해당 예측 열의 R 번호는 유지되지만 fallback 예측을 그 레짐만의 조건부 추정이라고 할 수는 없다.

고정 scores/hard에서 원 목표 인덱스를 계측해 `x_tau → R_(tau+1)`, 최대 학습 목표가 `R_t`임을 확인했다(FOR-007). `R_(t+1)` 이후 목표를 100만큼 바꿔도 예측 변화는 **0**이었다. 마지막 학습 목표 `R_t`만 0.5 바꾸면 최대 예측 변화는 **0.014020530392187328**이었다.

`R_t=P(t+1)/P(t)-1`이므로 최신 목표는 `P(t+1)` 관측 후 완성된다. **결정을 P(t+1) 이후로 해석하면 shift 자체로 누출을 단정할 수 없다.** 같은 가격에 체결 가능한지, 거시 자료가 공개됐는지는 미정이다. 이 검사는 고정된 회귀 입력의 상한 확인이며 실제 공개시점·전체 전처리 미래 변경 검사를 대체하지 않는다.

### Step3 fallback의 별도 RidgeCV 경로

Step3 원 코드에는 `fit_intercept=True`, `LeaveOneOut()`, `scoring="neg_mean_squared_error"`가 명시되어 있다. 실제 원 모델 생성·적합·예측 AST를 실행하자 독립 재적합과 λ·MSE·계수·절편이 일치했다(FOR-008). seed=4 반례에서 해당 경로의 별도 후보 구간 `1e-3…10`은 λ=10, MSE=1.3084925251236605를 선택했다. **R2 기본 scoring 오류가 아니다.** Step2의 후보 구간 `1e-4…100` 및 analytic CV와 별도 구현이므로 같은 결과를 가정하지 않는다.

## 집계와 날짜 연결

정상 확률 `[.5, .1, .15, .05, .1, .1]`에서 원 Step3은 **R1~R5만** 가중합해 합성 두 자산 예측 `[.0115, .0145]`를 반환했다. R0 예측 열을 크게 바꾸어도 결과는 같았다(FOR-009). 이는 인쇄 식14의 합산 범위 준수다. 위기 활용의 의미와 R0 제외는 방법론 문서의 AMB04로 남긴다.

일반 레짐 확률 합 0.5를 재정규화하면 두 예측에 같은 양의 배율 2가 적용된다. 원 lo 함수의 비중은 두 경우 모두 `[23/52, 29/52]`로 같았다(FOR-010). 원문은 재정규화를 요구하지 않으며, **재정규화 부재만으로 lo 비중 오류라고 판단하지 않는다.**

경계와 연결 문제는 별도 기록했다.

| ID | 원 코드 실제 결과 | 판단 범위 |
|---|---|---|
| FOR-011 | R0=1, 나머지 확률=0이면 균등확률로 바꿔 예측 `[.018, .03]` 생성 | 인쇄 식14는 `[0,0]`이므로 경계 불일치. 실제 운용에서 발생했는지는 미확인. |
| FOR-012 | Step1에서 한 날짜를 빼면 Step2의 3개 날짜 중 2개만 출력 | inner merge가 불일치 날짜를 조용히 삭제하는 완전성 반례. |
| FOR-013 | 같은 날짜가 Step1에 3개, Step2에 2개 있으면 그 날짜 6행·총 8행 출력 | 월별 일대일 연결을 보장하지 않는 중복 입력 반례. |
| FOR-014 | R3의 A 예측 열이 없으면 A는 NaN, B는 유지; p_R3=0이어도 A는 NaN | 누락 셀 처리의 실제 정책. 논문이 유일한 결측 정책을 정하지는 않음. |

날짜 누락·중복 검사는 원 집계 AST에 주입한 합성 사례다. 실제 생산 CSV의 누락·중복 빈도를 추정하지 않았다. 원문이 구체적인 오류처리 방식을 정하지 않은 사실과 파이프라인에서 일대일 월별 연결을 검증하지 않는 사실을 분리한다.

## 원 lo 비중 함수

FOR-015는 l=2/3/4 각각에 대해 양수 상위 l개, 양수 부족, 모두 비양수, 경계 동률을 실행했다. 양수 종목이 있으면 선택수는 `min(l, 양수 개수)`, 순노출·총절대노출은 1이고 음의 비중은 없다. 모두 비양수이면 비중·노출은 0이다. 동률은 특정 종목 ID를 정답으로 강제하지 않고 선택된 값·개수·비율을 검증했다. 현금 fallback과 동률 종목 순서는 원문이 정하지 않은 구현 선택이다.

FOR-016은 NaN/Inf 입력 정책을 실행해 다음을 관측했다.

- NaN과 음의 Inf는 양수 마스크에서 제외된다. 나머지 양수 `[2,1]`은 `[2/3,1/3]`으로 배분된다.
- 양의 Inf가 선택되면 `S_l=Inf`이므로 모든 비중을 0으로 반환한다. metadata의 `n_selected=2`와 실제 비중이 양수인 종목 수 0은 다르다.
- 모든 값이 NaN·음의 Inf·비양수이면 현금을 반환한다.

반환 비중은 이 사례에서 유한하지만 metadata의 `S_l=Inf`는 그대로다. 원문이 NaN/Inf의 경제적 처리 기준을 정하지 않았으므로 여기의 PASS는 **실제 분기와 유한 비중을 확인했다는 뜻**이다. 일반적인 데이터 정제 또는 입력 오류 알림이 충분하다는 판정이 아니다.
